# APAF-1 column (paymnts) — AP2 #402 independent-verifier interop

`apaf1-column.json` is the APAF-1 verdict column (paymnts decision layer) over the pinned third-party wire fixtures used for the independent-verifier crosswalk in google-agentic-commerce/AP2 issue #402, alongside the AMEP and AER-1 columns.

Fixtures (SHA-256, recomputed before judging; matches the published pins in zambodotdev/aer1-kit `interop/`):

- sdk family: `sdk-bundles.json` `7e1dd6d97003d11f61ee2b60625bc1fff282d9a5f1eaa7426b276bbd3140b61f`
- synthetic family: `bundles.json` `bd530228cb9880d33f49016ab85f426a6c0e9668f3b6e47734b4aa779a71c4fc`
- sdk_v2 family: `sdk-bundles-v2.json` `70626262730fd4e057fb49aa5a404268f8e8192d6b1d3b0f460d3eb5c4a63a05` (AMEP PR #21 head `785123c59b61` — the same 8 SDK bundles regenerated with closed-checkout chains presented beneath each payment mandate, plus two rows authored against the `payment.reference` binding)

Join key: bundle name + payment index (a closed mandate presented twice is one over-redeemed payment, not a second one — 25 presentations, 22 payment rows in the v1 families; 11 rows in sdk_v2).

## What the column judges

Decision semantics on the presented artifacts, including cumulative mandate state (spend, use count, closed-mandate replay) carried across the bundle — the cross-payment state a single-record judgment cannot carry. Open-mandate expiry is judged at each hop's `iat`. Every ES256 signature and every digest binding (sd_hash, issuer_jwt_hash, disclosure digests, receipt references) is recomputed.

Vocabulary:

- `approved` — chain, signatures, bindings, constraints, receipt verify
- `declined` — hard failure: bad signature/binding, constraint violation, altered evidence, closed-mandate replay 
- `escalated` — a required check is unverifiable from the presented set (receipt absent or bound to another mandate, prior outcome unknown under stateful constraints)
- `not_evaluated` — processor reported a failed execution

Each row's `checks` detail and `evidence` codes are recomputable by any third party from the public fixtures — no APAF-1 code execution is required to audit a row. The `spec_schema` check axis reports conformance of the presented mandates to the ap2-protocol.org JSON schemas (finding published verbatim per row: in the v1 families every open payment mandate lacked the schema-required `payment.reference` constraint — AMEP confirmed the schema was right and its generator was behind it; the sdk_v2 family emits `payment.reference` and is conformant); it measures a different axis than decision semantics and does not drive the verdict.

For the sdk_v2 family the column also judges the checkout-mandate binding: `conditional_transaction_id` in the open payment mandate's `payment.reference` constraint must equal the presented checkout chain's issuer digest, and the payment's `transaction_id` must equal the closed checkout mandate's `checkout_hash` (`sdk-ref-other-checkout` → declined, `sdk-ref-checkout-absent` → escalated).

The column is generated by the paymnts APAF-1 production verifier path (`app/core/pymnts/ap2_wire.py`); generation script and test coverage are internal. Any row can be challenged by name — the finding is recomputable from the cited digests.
